# AGENTS.md

Quick-reference for AI agents working in this repo.

## Essential commands

```bash
pnpm dev          # start full dev stack (installs deps, pulls images, runs docker-compose.dev.yml)
pnpm dev:down     # stop dev stack
pnpm dev:prune    # stop and remove volumes (destructive)
pnpm db:reset     # reset Postgres databases via script inside the postgres container
pnpm nuke         # runs scripts/nuke.sh — cleans all repo artifacts
```

There are no dedicated test, lint, or typecheck scripts in the root `package.json`. Backend linting runs through the pre-commit hook only (see below).

## Package manager

**pnpm 10 only.** `npm` and `yarn` are blocked (`preinstall` script enforces this). Workspace config is in `pnpm-workspace.yaml` — currently only `web/` is a member.

## Dev environment

Everything runs in Docker. There is no supported local-only dev flow documented.

- `docker-compose.dev.yml` — dev stack (hot-reload, mounted volumes)
- `docker-compose.yml` — prod stack (Gunicorn, built images, named network `insure_iq_network`)

Nginx (dev) proxies everything on `:8080`:
- `/service-api/` → Django backend (`:8000`)
- `/auth/` → Better Auth service (`:10000`)
- `/` → Nuxt frontend (`:3000`)

### Backend (Django 5.2 / Python 3.12)

- Settings module: `config.settings`
- Celery app: `config.celery` (autodiscovers tasks from all apps)
- Custom user model: `accounts.User` (`AUTH_USER_MODEL = 'accounts.User'`)
- Auth: JWT validated against external Better Auth service via `config.authentication.JWTAuthenticationMiddleware`
- Media storage: MinIO (S3-compatible) via `django-storages`
- OpenAPI schema: `drf-spectacular` at `/api/schema/`, Swagger at `/api/docs/`

Django apps:
- `accounts` — user/auth models and views
- `core` — health check, shared utilities
- `policy_extract` — policy extraction pipeline (has dedicated Celery queue)
- `commission_intake` — commission intake pipeline (has dedicated Celery queue)
- `system` — system-level models/views
- `cins` — shared library (not a Django app; processors, prompts, schema, validators)

Entrypoint (`backend/entrypoint.sh`) accepts commands: `dev`, `prod`, `celery`, `celery-policy-extract`, `celery-commission-intake`, `beat`.

### Frontend (Nuxt 4 / Vue 3 / Node 24)

- Config: `web/nuxt.config.ts`
- Routes: `web/app/pages/` (file-based)
- State: Pinia stores in `web/app/stores/`
- Styling: Tailwind CSS 4 via `@tailwindcss/vite` plugin
- ESLint: `web/eslint.config.mjs` — extends `.nuxt/eslint.config.mjs` (generated by `@nuxt/eslint` module)
- TypeScript config references `.nuxt/tsconfig.*.json` (generated by Nuxt)

## Pre-commit hooks

Husky (`.husky/_/`) runs on every commit. Backend uses `.pre-commit-config.yaml` with these hooks:

- **ruff** (lint + format)
- **black** (formatter)
- **isort** (import sorter, profile=black)
- **flake8** (max-line-length=88, extend-ignore=E203)
- **autoflake** (removes unused imports/variables)
- **mypy** (--check-untyped-defs --ignore-missing-imports)
- **prettier** (markdown, yaml)
- **codespell**

**Never use `--no-verify`** to skip hooks (enforced by project convention).

## Environment

Copy `.env.example` → `.env` at project root. All defaults work for local dev via Docker. Key env groups: `DB_*`, `AWS_*` (MinIO), `CELERY_*` (Redis), `NUXT_PUBLIC_*`, `BETTER_AUTH_*`, `WEBHOOK_*`.

## Releases

Managed by `release-it`. Running `pnpm release` creates a GitHub release and bumps version in `web/package.json` and `web/src/constants/VERSION.ts`. Release commits use `--no-verify` (configured in `release-it` config).

## Things an agent might get wrong

- Backend migrations auto-run on container start (entrypoint). You don't need to run `migrate` manually in dev.
- The `celery` entrypoint arg runs the default worker; specialized workers use `celery-policy-extract` and `celery-commission-intake` (they listen on named queues, not the default queue).
- `cins/` is a shared library, not a Django app — it has no `apps.py`, `models.py`, or `urls.py`.
- The frontend's `eslint.config.mjs` imports from `.nuxt/` which is generated — run `pnpm install` in `web/` before ESLint works.
- File uploads go to MinIO, not the local filesystem. The `STORAGES["default"]` backend is S3Boto3Storage.
- CORS is fully open in dev (`CORS_ALLOW_ALL_ORIGINS = True`). Don't tighten this without understanding it will break the proxy setup.
